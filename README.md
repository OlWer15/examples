# QA-шпаргалка

Статический сайт для тестировщика: чек-листы по частям интерфейса и генератор тестовых данных. Без сборки и зависимостей — всё работает в браузере, данные никуда не отправляются.

## Что есть

- **Чек-листы** — 18 штук по разделам:
  - *Ввод данных:* поле ввода, область ввода, плейсхолдер, чекбокс, радиокнопка, выпадающий список (select/combobox), загрузка файла, форма;
  - *Навигация:* главное меню, контекстное меню, ссылка, полоса прокрутки, раскрывающийся список (аккордеон/спойлер/дерево);
  - *Кнопки и отображение:* кнопка, иконка, надпись, подсказка (тултип);
  - *Данные:* таблица и список.

  Отметки сохраняются в браузере (`localStorage`), есть «Скрыть отмеченные» и «Скопировать отчёт» (Markdown с `- [x]`, чтобы вставить в задачу или тест-ран). На странице чек-листа — «хлебные крошки» с разделом, переключатель на другой чек-лист и «← предыдущий / следующий →». Разделы и порядок задаются в `window.CHECKLIST_CATEGORIES` в конце `data/checklists.js`; `checklist.html` без `id` показывает выбор чек-листа, с неизвестным `id` — «Чек-лист не найден».
- **Свои пункты и группы** — под особенности проекта или сферы: «+ Добавить пункт» в любой группе (текст + необязательная подсказка), «+ Добавить свою группу» в конце чек-листа. Свои пункты помечены «свой», их можно изменить (✎) и удалить (✕); встроенные не трогаются. Участвуют в прогрессе, поиске и отчёте. У своих пунктов постоянный id — правка текста не сбрасывает отметку. Если встроенную группу переименовать в `data/checklists.js`, её свои пункты не пропадут — окажутся в «Прочих своих пунктах».
- **Экспорт / импорт своих пунктов** (на главной и на странице чек-листа) — один JSON-файл со своими пунктами всех чек-листов. Импорт сливает по id: повторный импорт того же файла дублей не создаёт, а файл коллеги добавит его пункты к вашим. Важно: браузер хранит данные отдельно для каждого адреса — открытый двойным кликом `index.html` и `http://localhost:8765` видят разные свои пункты; переносите их экспортом/импортом.
- **Поиск** на главной по всем пунктам и подсказкам, включая свои; клик ведёт прямо к пункту.
- **Генератор** (`generator.html`):
  - *Граничные значения* — для длины строки, целого, дробного числа и даты: min−1 … max+1 плюс ловушки (пробелы, эмодзи, `1e3`, 29 февраля и т.п.). Таблица копируется в Markdown с пустой колонкой «Факт».
  - *Строки-ловушки* — строка любой длины (counterstring `*3*5*7…`, латиница, кириллица, иероглифы, арабская вязь, эмодзи) со счётчиком символов, UTF-16 и байт UTF-8; готовые наборы: юникод, невидимые символы, HTML/шаблоны, SQL-спецсимволы, имена файлов, email, числа.
  - *Тестовые данные* — поля: имя, фамилия, отчество, почта, телефон, ИНН (РФ, валидный), серия и номер паспорта (РФ, `4514 123456`), адрес, домен, URL, текст (1–3 предложения), набор слов (1–4). **Язык данных** — параметр: кириллица (русский), латиница (английский), иероглифы (китайский), арабская вязь (арабский) или «вперемешку» — у каждой строки свой. На выбранном языке — имя, фамилия, отчество, адрес, телефон, тексты; почта и домены — латиницей (из имени, для китайского — пиньинь). Отчество: русский — настоящее, по полу; английский — второе имя; арабский — имя отца; китайский — пусто (отчества нет). Поля выбираются в свёрнутом списке «Поля» (выбор нескольких, «Все», «По умолчанию», закрывается по «Готово», клику вне и Esc). «Сгенерировать» каждый раз даёт новый набор; экспорт CSV (с BOM для Excel) и JSON.
  - *Префикс* — помечает тестовые записи (`QA_`, `autotest_`, `test-{n}-`, `qa{date}_`), чтобы потом найти и удалить их одним запросом. Ставится в начало имени, фамилии, отчества, адреса, текстов, почты (только допустимые символы) и хоста в доменах и URL; телефон, ИНН, паспорт и ловушки не трогает. `{n}` — номер строки, `{date}` — дата ГГГГММДД. Смена префикса, колонок, языка или доли ловушек пересобирает тот же набор, не перемешивая его.
  - *Ловушки в данных* — 10/25/50% значений в почте, тексте, наборе слов, домене и URL заменяются пустыми, граничными и необычными (часть невалидна намеренно); в таблице они подсвечены.

Домены и email — только в зарезервированных под тесты зонах: `*.example.com/org/net`, `.test`, `.example` и IDN-тестовые зоны IANA (`пример.испытание`, `例子.测试`…), чтобы тестируемая система не отправила письмо реальному человеку.

Телефоны для английского — из диапазонов, выделенных регуляторами для кино и тестов (US `555-0100…0199`, UK `07700 900xxx`). Российские (+7), китайские (+86) и арабские (+971) номера случайные и могут существовать — не отправляйте на них SMS. ИНН физлица — с двумя валидными контрольными цифрами; паспорт — синтетический номер в формате РФ.

Оформление — мягкая синяя гамма, светлая и тёмная темы (переключатель в шапке, по умолчанию — как в системе).

## Как открыть

Двойной клик по `index.html` — или через локальный сервер (нужен Node):

```bash
node serve.js
```

и открыть http://localhost:8765.

## Структура

```
index.html, checklist.html, generator.html
data/checklists.js     # содержимое чек-листов — правится здесь
assets/style.css       # стили, светлая/тёмная тема
assets/common.js       # хранилище, тема, шапка, копирование
assets/index.js        # главная и поиск
assets/checklist.js    # страница чек-листа
assets/gen-core.js     # логика генератора без DOM (работает и в Node)
assets/generator.js    # интерфейс генератора
serve.js               # мини-сервер без зависимостей
```

## Как добавить чек-лист

Дописать объект в `data/checklists.js` (`id`, `short`, `title`, `summary`, `groups` с `items`). Пункт — строка или `{ t: 'текст', h: 'подсказка' }`, `` `код` `` выделяется моноширинным. Ссылка в шапке и карточка на главной появятся сами.

Отметки привязаны к тексту пункта: если текст поменять, отметка этого пункта сбросится.

## Для автотестов

На ключевых элементах есть `data-testid` в формате `scope:name` (`nav:link-form`, `checklist:item`, `boundary:row`, `data:generate`…) — сайт можно использовать как полигон для Playwright.
